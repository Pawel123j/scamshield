# Temporary dependency security patch

`braces@3.0.3` has no patched release for GHSA-vfj7-8cjw-p6xm in the registry at validation time (2026-10-18). Its parser now rejects AST nesting beyond 128 levels, including braces and parentheses, before recursive compilation/stringification/expansion. Normal glob expansion and ranges remain supported. Untrusted prebuilt AST objects are outside the string-pattern API used by these build tools.

`npm ci` applies the versioned patch with `patch-package --error-on-fail`. `npm run security:check` queries the full npm audit, always verifies the installed parser SHA-256 and version for the root braces installation, plus **every additional reported braces installation**, runs deeply nested/unfinished/mixed pattern regressions plus valid pattern checks, and fails on any other low/moderate/high/critical advisory or unavailable audit. This exact advisory is considered mitigated only with that evidence. The raw audit may still report the locked version: a source patch does not change the package version. Report the dated raw result separately from patch verification.

The exception expires on **2026-12-16** and must be reviewed against upstream. Remove the patch and exception when a compatible fixed release is available. The gate also fails if the patch is absent, modified, or applied to another version. Moderate selector-parser issues are addressed with 7.1.6 and the production build/E2E verify compatibility.

Dependency refresh validated on 2026-10-24 with Node.js 24: Vite 8.3.5 and Vitest/mocker 5.0.5. These replace the newly reported vulnerable versions without removing this parser patch or weakening the gate. The registry still lists braces 3.0.3 as its latest release; the original review deadline was 2026-11-18.

Registry recheck on 2026-11-16: `npm view braces version` still returns 3.0.3; `micromatch@4.0.8` still depends on `braces:^3.0.3`. No compatible fixed upstream release was found. An independent read-only review inspected the parser and public string APIs: the depth check runs before both brace and parenthesis child nodes are inserted into the AST. Revalidated the source hash and clean-install patch application. Added repeatable gate coverage for exact allowed depths 127/128, rejected depth129 through default/create/array/expand APIs (also with maxLength:Infinity), mismatched mixed nesting and literal character classes. Existing depth4000 single-delimiter cases exercise nesting rejection; depth10000 cases can hit the separate maximum-input-length limit and are not counted as evidence for the nesting patch. An in-memory comparison removing only the six patch lines reproduced `RangeError: Maximum call stack size exceeded` in unpatched expand (braces) and stringify (parentheses) at depth4999 with a single `x` leaf: 9999 characters, below the separate input-length cap. The patched APIs reject these with the intended nesting `SyntaxError`; this 9999-character regression is now in the gate. Escapes, quotes, ordinary globs/ranges and many shallow groups remain valid.

On this evidence, the review deadline was renewed from 2026-11-18 to **2026-12-16**. It still fails closed at expiry, on any hash/version drift, on attack/compatibility regression or an unavailable audit. The patch is a temporary mitigation for string patterns, not a general guarantee for caller-built ASTs or unrestricted combinatorial brace expansion. Recheck upstream before renewal; remove the patch when a compatible fixed release is available.

The 2026-11-16 raw audit found GHSA-g3hv-75wg-m249 in minimatch 10.2.6 through typescript-eslint. A targeted `@typescript-eslint/typescript-estree` override uses fixed minimatch 11.0.1; older minimatch 3 consumers remain unchanged. This major override requires lint/typecheck/build compatibility checks. The security gate now rejects unmitigated findings at every reported severity, including low/moderate.

Final local verification on 2026-11-16: clean npm ci, lint, typecheck, 71 Vitest cases, production Next.js build and three sandboxed Chromium browser scenarios passed. Raw npm audit: zero known advisories; patched-parser verification and attack/compatibility checks passed independently of that feed result. These are dated observations, not a future guarantee.
